# phone-filter — 电话号码文本处理器 设计文档

## 概述

`phone-filter` 是一个独立的 Go CLI 工具，用于解析包含 `11位数字----有/无` 格式行的文本文件，根据用户指定的号段前缀进行筛选统计，并生成结构化的分析报告。

完全兼容 CLI Hub Tauri 协议，支持 `--schema`、`--version`、`x-steps` 多步骤向导、双语界面。

## 核心流程

```
输入（文件/stdin） → 解析 → 匹配筛选 → 统计 → 生成报告 → 输出文件
```

1. **读取输入** — 从 `--input-file` 指定的文件读取，若为空则从 stdin 读取
2. **逐行解析** — 正则 `^\d{11}----(有|无)$` 匹配有效行，不符合的行收集到忽略列表
3. **按前缀分组** — 根据 `--prefixes` 参数按 `;` 分割得到多个"轴"，每个轴对有效行做前缀匹配
4. **统计** — 每个轴内按 有/无 分别计数，计算占比
5. **生成报告** — 按固定格式输出，末尾附加数据质量提醒
6. **写入文件** — `--output` 为目录时生成时间戳文件名，为文件时直接覆盖

## CLI 参数

| Flag | 类型 | 默认值 | 必填 | 说明 |
|---|---|---|---|---|
| `--input-file` | string (`file-path`) | `""` | 否 | 输入文本文件路径。为空时从 stdin 读取 |
| `--prefixes` | string | `;` | 否 | 分号分隔的前缀模式。空段 = 全量数据。例：`;123;456;` |
| `--show-details` | boolean | `false` | 否 | 勾选后在报告中包含每个轴的详细匹配数据行 |
| `--output` | string (`directory-path`) | `""` | **是** | 输出路径。目录 → 生成 `YYYYMMDDHHmmss.txt`；文件 → 直接覆盖 |

### x-steps 向导

- **步骤 1 — 选择文件：** `input-file`、`output`
- **步骤 2 — 筛选选项：** `prefixes`、`show-details`

## 前缀匹配规则

- `--prefixes` 按 `;` 分割为多个"轴"
- 空字符串段（两个连续 `;` 之间为空，或开头/结尾的 `;` 导致空段）= **全量数据**轴
- 非空段为数字前缀，按位逐位匹配（前缀 5 位就比前 5 位，前缀 8 位就比前 8 位）
- 中间空格自动 trim

**示例：**

| 输入 | 解析结果 |
|---|---|
| `;` | 仅全量数据 |
| `;12342187;55694315;` | 全量数据 → 12342187 → 55694315 |
| `12342187;;55694315;` | 12342187 → 全量数据 → 55694315 |
| `12342187;55694315;;` | 12342187 → 55694315 → 全量数据 |

## 输入解析

### 有效行格式

```
^\d{11}----(有|无)$
```

- 11 位数字（手机号） + `----` + 有/无
- 每行独立匹配，行内其他内容不影响（如前后有空白，trim 后匹配）

### 无效行处理

不符合上述格式的行：
- 统计时忽略，不计入任何轴的 有/无 计数
- 在报告末尾汇总提醒

## 报告格式

### 每个轴的报告块

```
--------------------------------------------------------------------------------------------------------------------------------------------------------------------------

>>>>开始>>>><轴标签>

<轴标签>----有  =  N  (个)
* 13800138000----有
* 13800138001----有
...
<轴标签>----无  =  N  (个)
* 13800138002----无
...

<轴标签>----有  =  占比为 XX.XX%
<轴标签>----无  =  占比为 XX.XX%

<<<<结束<<<<<轴标签>
```

- `<轴标签>` = 用户输入的前缀数字，或 `全量数据`（空段时）
- 详细数据行（`* xxx`）仅在 `--show-details=true` 时输出
- 占比保留两位小数
- 当某轴匹配数据为 0 条时，有和无都显示 `占比为 0%`

### 报告末尾 — 数据质量提醒

```
========== 数据质量提醒 ==========
以下 N 行不符合 `11位数字----有/无` 格式，已忽略：
* 原始行内容1
* 原始行内容2
...
```

仅在存在无效行时输出。

### 多轴报告顺序

按 `--prefixes` 解析后的顺序依次输出各轴报告块，报告之间用分隔线隔开。

## 输出文件命名

- `--output` 为**目录** → 生成 `YYYYMMDDHHmmss.txt`（如 `20260603143052.txt`）
- `--output` 为**文件路径**（以 `.txt` 结尾）→ 直接使用该路径，覆盖已有内容

## 退出码

| 码 | 含义 |
|---|---|
| 0 | 成功 |
| 1 | 参数验证错误（如 `--output` 为空） |
| 2 | 运行时错误（如文件读取失败） |

## 协议兼容

- `--schema` 输出 JSON Schema 后退出
- `--version` 输出 `phone-filter v0.1.0 (protocol v1)` 后退出
- 成功时最后一行 stdout 输出 `{"status":"ok","output":"报告已生成至 <path>"}`

## 边界情况处理

| 场景 | 行为 |
|---|---|
| 输入文件为空 | 有/无 计数均为 0，占比 0%，报告正常生成 |
| 无任何有效行 | 每个轴报告均为 0，数据质量提醒无内容（不输出提醒段） |
| `--prefixes` 为空字符串 | 等同于 `;`（仅全量数据） |
| `--prefixes` 包含非数字字符 | 参数验证报错，退出码 1 |
| `--output` 目录不存在 | 自动创建（`os.MkdirAll`） |
| 输入含 BOM 或前后空白 | trim 后再匹配 |
| 前缀位数 > 11 | 参数验证报错，退出码 1 |
| 全量数据轴匹配数 = 0 | 正常输出报告，计数和占比均为 0 |
